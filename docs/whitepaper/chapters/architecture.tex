\chapter{System Architecture}

The trading bot coordinates data ingestion, signal generation, execution, and risk monitoring through modular components orchestrated by the \texttt{TradingEngine}. Figure~\ref{lst:engine} highlights the bootstrapping sequence defined in \texttt{src/engine.py}.

\begin{lstlisting}[language=Python, firstnumber=1,label={lst:engine},caption={Trading engine initialisation excerpt}]
# src/engine.py (abridged)
self.dh = DataHandler(paper_trading=True)
self.eh = ExecutionHandler(paper_trading=True)
self.pm = PortfolioManager(self.dh)
self.sm = StrategyManager(self.dh, self.eh, self.pm)
self.option_data_handler = OptionDataHandler(self.dh)
self.multi_leg_helper = MultiLegExecutionHelper(self.eh)
self.universe_manager = UniverseManager(...)
self.rebalance_strategies()
self.sm.reconcile_positions()
\end{lstlisting}

\section{Data Layer}
Historical and intraday bars are sourced through the Alpaca \texttt{StockHistoricalDataClient} inside the \texttt{DataHandler} (see \texttt{src/data_handler.py}). The mapping from textual timeframes (``1H'', ``1D'', etc.) to \texttt{alpaca-py} objects is strict, ensuring deterministic sampling windows. For a symbol $s$ and timeframe $\Delta t$, the handler returns a frame $\{(t_i, o_i, h_i, l_i, c_i, v_i)\}_{i=1}^N$ with timestamps aligned to UTC.

\section{Execution Layer}
The \texttt{ExecutionHandler} (\texttt{src/execution.py}) translates abstract signals into Alpaca order requests. Market and limit orders are supported through
\begin{equation}
\text{Order}(s, q, \text{side}, \text{type}, \tau),
\end{equation}
where $s$ denotes the traded symbol, $q$ the quantity, $\text{side} \in \{\text{buy}, \text{sell}\}$, $\text{type} \in \{\text{market}, \text{limit}\}$, and $\tau$ the time-in-force instruction.

\section{Portfolio Governance}
The \texttt{PortfolioManager} (\texttt{src/portfolio_manager.py}) enforces per-strategy budget limits. Each strategy $k$ receives an equity allocation $A_k$ with leverage $L_k$. A trade proposal with estimated cost $C_k$ and current exposure $E_k$ is approved if
\begin{equation}
E_k + C_k \leq A_k L_k.
\end{equation}
Live equity is refreshed through brokerage API calls with a fallback cache when unavailable.

\section{Strategy Orchestration}
The \texttt{StrategyManager} (\texttt{src/strategy_manager.py}) maintains the active strategy set $\mathcal{S}$. At each heartbeat the manager:
\begin{enumerate}[label=\arabic*.,noitemsep]
    \item Queries the \texttt{RegimeDetector} for the prevailing volatility regime $R_t$.
    \item Skips strategies whose profiles conflict with $R_t$ (e.g., suppress pairs trading under high volatility).
    \item Invokes \texttt{generate\_signal()} on each remaining strategy and forwards approved orders to execution.
\end{enumerate}

\section{Universe Management}
Candidate assets are generated by the \texttt{UniverseManager}, which screens the symbol list for statistical features (e.g., cointegration for pairs trading). The resulting watchlist modulates which strategy configurations are spawned during \texttt{rebalance\_strategies()}.
